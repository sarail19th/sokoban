# Box Pusher

Single-file Sokoban-style puzzle for Android Chrome (a Sokoban-style box-pushing mini game).
Push boxes onto stars using an on-screen d-pad or swipes. 30 stages, stage list with par, Undo, Restart, Hint,
per-stage best moves, installable PWA.

## Layout
- `index.html` — the whole game (HTML + CSS + JS, no dependencies); works on its own when opened as a file
- `manifest.webmanifest`, `sw.js`, `icon-192.png`, `icon-512.png` — optional PWA extras (install + offline)
- `tools/solve.js` — uses the game's own `solveBFS` to prove every stage solvable and optimal, re-plays each answer in an
  independent engine, writes/checks `SOLUTIONS`; `tools/par-cache.json` caches proven answers (keyed by layout)
- `tools/make-icons.js` — renders the PNG icons (no dependencies)
- `tools/sprite-editor.html` — standalone editor for the player's look (see Features)
- `tools/pixel-editor.html` — standalone pixel editor for the character (all 16 frames) and the tiles (see Features)

## Rules for changes
- The game stays ONE self-contained `index.html` (no build step, no external assets, no libraries).
  The PWA files are the only extras and the game must still work without them (file://).
- Mobile first: touch via `pointerdown`, no hover, viewport locked, canvas scales with CSS.
- Stages live in the `LEVELS` array in `index.html`; `STAGE_NAMES` (same order) feeds the stage list.
  Legend: `#` wall, ` ` floor, `.` star, `$` box, `@` player, `_` outside (non-walkable, outside the room).
  Rows may be ragged; short rows are padded with `_`.
- **Win = every star has a box on it.** Spare boxes (more boxes than stars) are allowed and stages use them
  ("Flask", "Shaft", "Cross Room"). Never fewer boxes than stars.
- Stage order = difficulty score = par (proven minimum moves) + 25 x number of stars; ties by par. Spare boxes do not add
  difficulty, so a 6-box / 4-star stage sorts by its 4 stars. Insert new stages at their sorted position (best scores are keyed by
  layout, so reordering is safe).
- `SOLUTIONS` (right after `STAGE_NAMES`) is GENERATED by `node tools/solve.js index.html --write`; never edit by hand.
- localStorage keys, always inside try/catch: `bp_lvl` (last stage index), `bp_best2` (JSON `{layoutId: bestMoves}`,
  layoutId = hash of the stage's rows, so reordering stages keeps scores; editing a stage's layout resets its score).
  The old index-keyed `bp_best` is no longer read.
- `index.html` uses CRLF line endings; the solver preserves them when writing.
- If you change `index.html`, `manifest.webmanifest` or the icons, bump `CACHE` in `sw.js` so installed copies update.
- Watch out for `$$`/`$'` in JS `String.replace` replacement strings when scripting edits (it silently ate a `$` in a stage).

## Features (how they work)
- **Par / stage list**: header shows "N boxes · Par P · Best B". Tapping the "Stage N" title opens a list of all stages
  (name, boxes, par, best; best turns green when it equals par). Par = proven minimum number of moves.
- **Solver** (`solveBFS` in index.html, shared by HINT and `tools/solve.js`): A* over push-states (boxes + player position
  after a push; walking between pushes is one BFS flood). Heuristic = cheapest assignment of boxes to stars by push
  distance (never overestimates, so results stay optimal). Dead squares are pruned only when boxes == stars.
  `limit` = max states; returns a UDLR string (lowercase = push), `null` (unsolvable) or `-1` (gave up).
  "Cross Room" (6 boxes) needs ~10M states / ~4 min offline, so it is cached in `tools/par-cache.json`.
- **Hint**: HINT button replays an optimal path at ~170 ms/step. If the current state lies on the precomputed
  `SOLUTIONS[stage]` path it uses the rest of it; otherwise `solveBFS` runs in a Blob Web Worker from the current
  state (limit 400k states; `null` => "Stuck! Undo or restart", `-1` => "Too complex from here: Restart, then Hint").
  Any manual move, undo, restart or stage change stops playback. Using a hint disables recording a best score.
- **Best moves**: recorded on win (no hint used), shown in the header and the stage list.
- **Stars** (`starsFor`): 3 = moves <= par, 2 = moves <= 1.5 x par, 1 = passed (any hinted clear is 1). Best stars per
  stage are kept in `bp_stars` (`{layoutId: stars}`, never lowered) and shown in the win dialog and the stage list,
  whose top line summarises the whole game ("Cleared X/30 · ★ Y/90 · Perfect Z").
- **Desktop mode** (CSS media query `(hover:hover) and (pointer:fine) and (min-width:700px)` + `desktop()` in JS): the app uses the whole window,
  the on-screen d-pad is hidden (arrow keys / WASD instead), UNDO / RESTART / HINT / FULL SCREEN sit in one row, and `fitBoard()`
  sizes the canvas to the window with a whole-pixel tile size (on resize / fullscreenchange / stage load). Keys: arrows or WASD,
  Z undo, R restart, H hint, F full screen (Fullscreen API), Esc closes the stage list, Enter = next stage after a win. Shortcuts
  are ignored while typing in a text box or while the setup / stage-list screens are open. Touch devices keep the phone layout.
- **Swipe**: on the canvas, one move per ~0.8 cell of travel (so a long drag keeps walking); canvas has `touch-action:none`.
- **Player sprite**: `drawPlayer()` has 3 poses (`pose`: idle = standing still, walk = feet/arms alternate, push = leaning
  with arms out, squint, sweat, dust) and faces the last move direction (`facing`). `move()` sets walk/push; a timer
  (`setPose`) returns to idle ~220 ms (walk) / ~380 ms (push) later. Undo/load reset to idle.
- **Sprite editor**: `tools/sprite-editor.html` (open the file in any browser, no server needed). Style dropdowns
  (hair short/spiky/long/bun/bald, hat none/cap/beanie/crown/headband, outfit plain/stripes/overalls, extra
  none/glasses/scarf/backpack), colour pickers, presets, Random, live preview of all poses. "Copy" gives the
  `const PAL = {...};` and `const LOOK = {...};` lines to paste over the two in `index.html`.
  It embeds a COPY of `drawPlayer()`; after changing the function in `index.html`, paste the new copy into the editor
  (replace its `function drawPlayer` block). `node tools/solve.js` fails if the two drift.
  Adding a style option = add a branch in `drawPlayer()` + the value in the editor's `OPTIONS` (and default/preset
  colours if it needs a new `PAL` key + `DEFAULT`/`LABELS` there). The game's default character is the "Sakura" preset
  (`CHAR_PRESETS`); the style editor's Reset still goes back to the original blue one.
- **Start screen / setup** (`#setup`, JS block after `const $`): shown on first visit and via "Character & tiles" in the stage
  list. Step 1 pick a character (6 presets + Custom; the default is Aoba), step 2 pick a tile set (Classic, Treasure, Cherry, Stone & grass +
  Custom), then Play, which opens the stage list so the player picks any stage. Choices persist in `bp_setup`; pasted custom code in `bp_custom` (raw text, re-parsed on load).
  "Custom art" box accepts the code copied from the editors: `const PAL/LOOK` lines (styled character),
  `const PLAYER = {...}` (pixel character, 16 frames `idle|walkA|walkB|push` x `d|u|l|r`) or `const SPRITES = {...}` (tiles:
  floorA floorB wall box boxOn star). Sizes are 32 or 64 px; `T` (canvas pixels per tile) = the larger of the tile set and the pixel character, smaller sprites are scaled up
  with nearest neighbour (`rebuildSprites`), so Aoba's 64 px frames make T = 64.
  Rows use `.` = transparent and 0-9a-zA-Z = index into the sprite's palette `p`.
- **Aoba** (`AOBA_ART` in the CHARS block): traced from a reference picture: 18x18 art cells (front `d`, side `r`, back `u`;
  left = mirror of right; rows 16-17 are the ground shadow). `bakeArt` turns it into 16 frames of 64x64 (1 cell = 3x3 px): walk =
  hop 1 cell (B also flips front/back or steps sideways), push = lean 1 cell + sweat drop, shadow stays on the ground.
  The back view was drawn by hand from the front view; the side view (`r`) is traced from a second reference sprite (11x15 cells + outline, one hair row dropped to fit; yellow key `e` added to the palette). Styled presets (the others) are baked with `bakeLook`.
- **Shared code**: the tile generator (`originals()`, `LOOKS`: Treasure chest / Cherry / Stone wall / Grass floor),
  `CHAR_PRESETS` and `drawPlayer()` live in index.html between `// @@TILEGEN-BEGIN/END` and `// @@CHARS-BEGIN/END`.
  `tools/pixel-editor.html` holds copies; when they change, copy the marked blocks (and the drawPlayer function)
  over into the editor. `node tools/solve.js` fails if the copies drift (also for `tools/sprite-editor.html`'s drawPlayer).
- **Pixel editor** (`tools/pixel-editor.html`, open the file in any browser): "Character" or "Tiles"; 32x32 or 64x64 (converts);
  pencil / eraser / fill / picker, mirror, flips, undo/redo, PNG import. Character mode starts by baking a preset look (or
  PAL/LOOK lines pasted from the style editor) into 16 editable frames, so face and clothes can be painted; "same edit on all
  4 poses of this direction" repeats strokes across Stand/Walk A/Walk B/Push. Tiles mode has the tile looks. "Copy" gives the
  code to paste on the start screen.
- **PWA**: `sw.js` precaches the files, stale-while-revalidate; registered only on http(s).

## Verify after every change
1. `node tools/solve.js index.html` — must exit 0 (every stage solvable, replay OK, `SOLUTIONS` up to date, sprite editor
   in sync). After adding or editing any stage run it with `--write` first, then without. Run `--prove` (slow, ~4 min,
   ignores the cache) after changing `solveBFS`.
2. Test in a browser at phone width (~390px): d-pad, hold-to-repeat, swipe, Undo, Restart, Hint, stage list, stage
   switching, win dialog, best score. Service worker needs http://localhost (e.g. a tiny static server), not file://.
   If the service worker will not register in a test browser, check the profile path is short and use `localhost`.

## Stage design
- 15 stages were transcribed from reference screenshots (tile types read by colour-sampling, then sealed: floor the
  player can never reach becomes `_`): Ring, Cross Room, Flask, Cave, Maze, Bowl, Gap,
  Corridor, Spiral, Alley, Hut, Tunnel, Ledge, Shaft, Pocket.
- Shaped rooms Circle, Plus, Heart, Star were generated: build the room from a mask, put boxes on the stars, scramble
  with random legal reverse moves (solvable by construction), keep the hardest result the solver confirms.
- Hard stages Quarry (94), Catacomb (98), Labyrinth (144 moves): random cave rooms, boxes scrambled with reverse moves, then
  hill-climbed (extra reverse moves / wall toggles, keep if par grows) with the game solver; all 4 boxes.
- Older hand-made stages: Warehouse, Twins, Split, Diamond, Chamber, Gate, Crossroads, Hall. For new hand-made stages
  build backwards the same way and confirm with the solver.
- Box count up to ~4 solves in well under a second; 6 boxes in an open room is the practical limit (minutes).
